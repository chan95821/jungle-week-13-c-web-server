## 1. 측정 환경 및 공통 조건

- **시스템**: `Linux 7.3.6-1-cachyos-bore`, `nproc = 16`, `ip_local_port_range = 32768-60999`
- **빌드**: 격리 스냅샷 `-std=c11 -Wall -Wextra -Werror -O2` (`baseline`: `main` `577a554`, `current`: C안 `-pthread`)
- **부하 생성**: C 부하 생성기 `load_client` (요청마다 새 TCP 연결, `SHUT_WR`, 상태·`Content-Length`·1024B 패턴·`X-Backend-ID` 검증)
- **주의사항**: `Exp 1`·`Exp 3`의 `test_backend`는 단일 스레드 순차 백엔드이며, `Exp 2`의 `slow_backend`는 다중 느린 요청이 백엔드에서 직렬화되지 않도록 `pthread`로 요청마다 `800ms`를 동시 지연한다.

- **관찰**:
  - 큐 상한(`128`)을 넘는 `c=150` 동시 버스트에서도 순수 배압(Option A)이 커널 백로그와 조화롭게 동작해 **실패 `0`**, FD 누수 `0`을 기록했다.
  - 메모리(`VmRSS` 피크)는 `w=1` `2,416 KiB` → `w=32` `4,364 KiB`로 스레드 32개 기준 약 `+1.9 MiB`만 증가했다.
  - 반면 worker를 늘리는 방식은 `w` 이상의 느린 연결이 몰리면(`Exp 2` `K >= W`) 여전히 스레드 고갈이 발생하므로, 대규모 I/O 동시성은 A·B(`epoll`)가 유리함을 실험적으로 확인했다.
