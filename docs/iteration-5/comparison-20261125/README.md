## 장애 최소 확인

동일한 jaeseong C 테스트 백엔드, 각 모델 4작업자. 세 구현 모두 정상 제출 binary echo 201, 조회 200, 제출 백엔드 연결 거절→502 및 서버 생존, 무응답→504, 백엔드 정상화 후 201, 클라이언트 RST 10회 후 /hello 200, SIGTERM exit 0. FD 합계 전/후 jaeseong 15→15, chan 6→6, YYJ 42→42. 단일 스냅샷과 10회는 누수 부재의 증명이 아니다.

응답 중단(truncate): jaeseong/chan은 클라이언트 IncompleteRead(7바이트 수신, 나머지 불완전), YYJ는 502. 동일 테스트라도 최종 HTTP 응답 시작 전 오류 탐지 여부에 따라 다른 결과가 가능하므로 어느 쪽이 오류라고 단정하지 않는다. 실제 시작 전/후 경계와 두 번째 오류 응답 미첨부는 별도 raw-wire 장애 검증이 필요하다.

YYJ에서 작업자 프로세스 1개 SIGKILL: 부모 생존, 자식 4→3, /hello 200. 자동 재생성은 확인되지 않았으며 기대하지 않는다. 두 스레드 모델은 스레드만 SIGKILL할 수 없어 N/A. 공유 mutex 보유 중 사망/복구, 중복회수·상태오염, 반복 worker 사망 등은 미시험이다.
