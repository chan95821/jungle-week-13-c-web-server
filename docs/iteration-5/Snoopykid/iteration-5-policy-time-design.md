# 분배 정책의 시간 구간 — 다음 선택

2026-11-25. 네 후보는 RR, Least Outstanding+동률RR, 시간기반+동률RR, 진행수·시간결합+동률RR 그대로다. 최종 알고리즘·평균·초기표본·노후화·실패반영·공식·설정입력은 미정이다. 이 문서는 시간 구간만 제안하며 계측 코드·성능 실행을 허용한 것으로 보지 않는다.

## 1 추천: backend 작업 구간과 worker 연결 구간을 분리

### backend
선택+예약이 성공하고 잠금을 해제한 뒤, 첫 nonblocking connect 시도 직전 CLOCK_MONOTONIC 시각부터 최종 backend 응답 프레이밍 검증 완료 시각까지다. 연결 대기·요청 송신·응답 헤더/본문 수신을 포함한다. 예약 잠금 대기·예약 해제 잠금 대기·프레이밍 완료 후 남은 client 출력·연결 drain은 제외한다. client 역압력 때문에 backend 수신 자체가 늦어지면 그 지연은 포함된다. 원 서버 내부 처리 시간만의 측정이라고 표현하지 않는다.

정상 완료 시각은 backend lifetime의 COMPLETE 호출 직전에 고정한다. release lock EBUSY가 통계 시간을 늘리지 않게 한다. 실패/취소도 종료 시각은 고정할 수 있지만 평균에 반영할지는 별도 정책이며 빠른 실패를 성공 표본으로 자동 처리하지 않는다. 1xx 또는 불완전 본문은 성공 표본이 아니다.

### worker
작업자가 FD 프레임 전체를 수신·검증해 연결 소유권을 공개한 시각부터, 그 연결의 HTTP/출력/마무리 및 연결별 자원 정리가 끝나 CLOSED를 enqueue하기 직전까지다. 요청 수신·로컬/프록시/CGI 처리·client 출력·기존 마무리·자원해제 대기를 포함한다. parent FIFO 대기·FD 전달 시간·CLOSED 전송 적체와 parent 수신 지연은 제외한다. parent outstanding은 기존대로 배정부터 CLOSED 반영까지 더 길게 보수적으로 유지한다.

따라서 worker 시간은 클라이언트가 본 전체 지연이 아니라 작업자가 소유한 연결의 체류 시간이다. 느린 요청·client·요청종류 혼합에 영향을 받는다. backend 시간과 수치의 의미를 구분하되, 이후 대표값 비교 계산 코드는 공통으로 사용할 수 있다.

worker가 측정한 구간·결과를 bounded CLOSED 프레임에 포함시켜 parent에 전달하는 변경이 필요하다. 원시 시각 두 개를 다른프로세스에서 빼는 대신 worker가 계산한 길이와 결과를 전달하는 안이다. 평균/결과정책 합의 후 프레임version·검증·메모리 비용·복구기록을 같이 변경한다. 지금 IPC를 자동 변경하지 않는다.

## 2 대안: 첫 최종 응답 바이트 준비 시간

backend는 connect 직전부터 최종 응답 헤더 검증까지, worker는 FD 인계 완료부터 client 최종 응답 헤더를 보낼 준비가 될 때까지로 줄인다. 긴 본문·느린 출력의 영향을 줄이고 헤더 준비 지연에 집중할 수 있지만 응답 본문 중간 정지와 전송 비용을 선택 점수에 반영하지 못한다. 1xx 첫바이트를 최종 응답으로 오인하지 않아야 한다. 본문 실패 후 표본을 유지할지 등도 별도 선택이다.

## 구현 후 검증 후보

주입 단조 시계로 시작/종료 경계를 정확히 검증하고, 실제fork/IO검증과 성능비교를 구분한다. 예약/해제잠금 지연 제외·역압력 수신지연 포함·잔여client출력 제외(backend)·worker마무리 포함·CLOSED적체 제외(worker), 1xx/부분본문/204/304·중복완료·과거세대·overflow/역행·종료중사망·elapsed/frame변조를 검증한다. 기존HTTP/오류정책을 바꾸지 않는다.

구간 선택 뒤 평균·초기/오래된표본·실패반영·결합식·동률·설정입력을 한 정책 묶음으로 제시한다. 실제 비교 측정은 지표·환경·기간·반복·작업자수 승인 후 별도로 실행한다.
