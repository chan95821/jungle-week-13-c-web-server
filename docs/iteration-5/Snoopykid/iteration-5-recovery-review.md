# Iteration 5 복구 범위·비용·장애 검증 검토

2026-11-25. 확정 사항과 승인 대기 제안을 구분한다. 자료구조·제품 코드 미확정/미구현.

## 이번 확정
- fork 전 익명 MAP_SHARED mmap을 생성해 자식만 상속한다. shm_open/독립 프로세스 참여 제외.
- process-shared robust mutex 사용. 초기화·속성 설정 반환값을 확인하며 지원 환경을 확인한다.
- 복구 후 계속 운영 목표. 작업자 하나 사망만으로 나머지 서비스 전체를 무조건 종료하지 않는다.
- 네 알고리즘 동일 상태 구조 비교는 유지. 대체 작업자·재시작 제한·성능 실행 승인 없음.
- robust mutex는 잠금 보유자 사망 감지다. 임의 메모리 손상, 잘못된 정상 갱신, 살아 있는 소유자의 정지/무한 루프, 통계 진실성을 감지·수리하는 기능이 아니다.

## 복구 범위 제안 (아직 선택 필요)
전제: 운영 중 한 프로세스의 비정상 종료, 살아 있는 부모와 다른 작업자, 손상되지 않은 복구 기록. 전원 장애/프로세스 전체 재시작 후 영속 복구는 범위 밖 제안.
사망으로 끊긴 공유 변경과 해당 작업자 예약은 복구 대상으로 한다. 죽은 작업자의 기존 TCP 연결은 복원/다른 작업자로 이관/자동 재시도하지 않는 안을 제안한다. 다른 작업자의 연결은 유지.
복구는 공유 mutex를 보유한 단일 담당자가 수행. 선택·완료 상태 갱신은 잠시 대기하지만 잠금이 필요 없는 기존 네트워크 I/O·로컬 응답은 다른 작업자에서 계속 처리 가능. 복구 담당 작업자의 루프는 복구 CPU 작업 동안 지연될 수 있다. trylock 후 보류/재개·회복 시간 상한·과부하 정책은 별도 미결정. 대기 중 완료 예약은 실제 backend 종료와 집계 반영 사이 지연이 생기므로 pending 상태 소유권 필요.
네트워크·파일 I/O/로그 쓰기·waitpid는 잠금 밖. 부모는 waitpid로 사망 확인한 뒤 공유 회수 요청을 수행. 복구에 필요한 메모리는 미리 확보하고 잠금 안의 힙 할당·전체 무제한 스캔은 피하는 설계 검토. 원장 상한·배치 복구의 정확성·동기화 비용은 자료구조 선택 후 구체화.

## 공통 불변 조건 제안
I1: backend b의 전체 outstanding = 유효한 모든 작업자 세대의 b 기여분 합계 = 원장을 채택하면 b의 ACTIVE 예약 수.
I2: 각 요청 예약은 유일한 (worker slot, worker generation, request slot/id generation)에 귀속, 유효한 backend index만 참조.
I3: 성공한 예약은 1회 증가, 정상/실패/취소/사망 회수는 최대 1회 감소. 카운터 underflow/overflow 금지.
I4: commit 이전 연산은 없었던 것으로, commit 이후 연산은 온전히 반영된 것으로 해석. 예약·카운터·순번·선택 통계의 허용된 변경이 서로 모순되지 않음.
I5: 종료 확인·회수 완료된 세대의 ACTIVE 기여분은 0, 다음 세대의 상태는 보존. 작업자 슬롯은 회수/채널 폐쇄 완료 전 재사용하지 않음.
I6: 통계는 유효 플래그·범위·표본 수·합의된 평균/정책 규칙에 맞음. 이 검사는 실제 backend 지연과 일치함을 증명하지 않음.
I7: 복구 완료 전 inconsistent 상태를 정상이라고 표시하지 않음. 공유 상태가 정상일 때만 선택/완료 처리 재개.

## ① 잠금 밖 작업자 종료
탐지: 부모 waitpid(WNOHANG)의 종료 결과와 슬롯/세대 매핑. SIGCHLD는 알림일 뿐 전체 결과를 반복 회수. IPC EOF는 조기 의심 신호, SIGSTOP·느림을 사망으로 간주하지 않음.
탐지 불가/한계: 살아 있지만 멈춘 작업자, backend가 이미 처리했는지 여부. 사망 확인 지연 동안 기여분은 잠시 남을 수 있음.
순서 제안: 부모가 해당 작업자 FD 신규 전달 중단 → 사망 확인 → 잠금 획득/필요한 owner-death 복구 선행 → 해당 세대만 retire/예약 해제 → 집계 검증 → unlock. 무조건 전체 카운터 0으로 초기화 금지.
진행: 다른 작업자 I/O 유지, 공유 상태 갱신은 해당 잠금 동안 대기.
성공: I1/I3/I5, 살아 있는 작업자 예약·선택 상태 보존. backend 시간 표본에 worker 죽음을 넣을지는 미결정.
실패 제안: 회수 근거 불일치 시 상태 사용 중단·부모 통지, 전체 안전 종료 여부 선택 필요.
비용: 작업자·backend별 기여표, 세대, 요청 원장 선택 시 슬롯; 사망 때 스캔 또는 목록 순회. 부모 사망 후 회수 책임은 별도 설계.
검증: 여러 작업자 ACTIVE 중 1개를 잠금 밖 SIGKILL. 회수 후 그 세대=0/나머지 기여 불변, 합계 일치, 살아 있는 작업자 정상 응답. backend 실행 중단/취소를 보장한다고 하지 않음.

## ② 카운터 수정 도중 종료
탐지: 다음 mutex 획득의 EOWNERDEAD + 유효한 갱신 기록/commit 상태. EOWNERDEAD만으로 어느 값이 반영됐는지 알 수 없음.
순서 제안: 다음 획득자가 복구 기록 검증 → 미commit 연산의 이전 값 복원 또는 commit 상태 완성 → 집계/원장/순번·통계 정합 검사 → pthread_mutex_consistent → 기록 안전 정리·unlock. 이후 부모가 사망 작업자 ACTIVE 예약 회수. 정상 commit된 다른 작업자 상태는 보존.
진행: 복구 담당자만 공유 상태 접근, 다른 작업자의 공유 갱신 대기, 독립 I/O는 유지.
성공: I1~I4/I6/I7. 부분 증가/감소·순번만 이동·통계만 갱신 등 혼합 상태가 남지 않음.
실패 제안: 기록 손상/불명확한 commit/ENOTRECOVERABLE이면 추정 복원 금지, 안전 종료 선택 필요.
비용: 정상 선택/완료마다 영향받는 이전 값·대상 ID·commit 기록, 메모리 순서/원자 commit 조건. 전체 공유 테이블을 매 요청 복사할 필요는 없으나 정확한 크기는 구조 선택 후 확정.
검증: 기록 준비 전/후, 원장·기여·전체 카운터·순번·통계 각 쓰기 사이, commit 직전/직후·unlock 직전 SIGKILL. 전후 둘 중 하나로만 복원, underflow/잔류·다른 요청 손실 0.

## ③ 중복·늦은 완료
탐지: 요청 ID/세대/ACTIVE 상태 대조. PID나 FD 번호만 신원으로 사용하지 않음. 로컬 완료 가드만으로 공유 갱신 중 사망 원자성을 보장하지 않음.
순서 제안: 요청 token 확인 → 동일 세대 ACTIVE이면 완료 변경을 하나의 트랜잭션으로 commit → 이미 완료/회수/이전 세대면 무변경. 새 작업자 슬롯은 새 세대. 완료 통계도 중복 반영하지 않음.
진행: 정상 갱신 수준 잠금, 다른 I/O 계속.
성공: I2/I3/I5/I6, 같은 token 재적용 결과 불변. ID wrap은 재사용 금지/시작 실패 등 별도 정책 필요.
실패: 범위 밖 token과 정상 과거 완료를 구분해 진단; 임의 backend 카운터 감소 금지. 오류 후 종료 범위 미결정.
비용: 요청 token·세대, 중복 검사용 상태 또는 집계형 대안의 별도 증명/로컬 기록.
검증: 동일 완료 2회, 회수 후 완료, 슬롯 재사용 후 과거 token, worker/request ID wrap 경계, 통계 중복 반영 없음.

## ④ 복구 담당자도 복구 중 종료
탐지: mutex가 inconsistent인 동안 다음 획득자의 EOWNERDEAD. consistent 호출 이후 사망이면 새 owner-death로 처리. mutex 자체가 파괴/손상됐거나 부모까지 죽은 경우는 이 보장 밖.
순서 제안: 원본 복구 기록을 재복구 완료 전 덮어쓰거나 폐기하지 않음. 다시 실행해도 결과가 같은 이전 값 복원, 집계는 누적 더하기가 아니라 원장에서 재계산/정확한 값 설정. consistent 호출/기록 정리 전후 각 경계 설계 필요. 새 담당자는 부분 복구를 이어도 I1~I7을 충족해야 함.
진행: 공유 갱신은 복구 완료까지 보류, 다른 I/O는 가능한 범위 유지. 반복 사망이 있으면 계속 운영의 시간 보장은 없음.
성공: 동일 복구 2회 이상과 순차 사망 후에도 한 번 복구한 결과, 정상 작업자 상태 보존.
실패 제안: 복구 불능은 안전 종료. 반복 재복구 시도/시간 제한은 별도 선택이며 임의 횟수 도입 금지. 대체 worker 재시작 제한과 혼동하지 않음.
비용: idempotent 복구 기록/진행 상태·재계산 비용. 복구 스캔은 원장 개수에 비례할 수 있음.
검증: 이전 값 복원·원장 순회·집계 설정·consistent 직전/후·기록 정리 각 지점에서 복구 담당자 SIGKILL. 다음 담당자 성공 또는 승인된 중단, hang/이중 감소 금지.

## ⑤ 공유 메모리 자체 손상
탐지 후보: 버전·크기·상한·인덱스·세대/상태 enum·유효/finite 통계·집계/원장 일치·복구 기록 무결성 검사. checksum은 우발 손상 일부 탐지 후보이지 임의 손상 방어 수단 아님.
탐지 불가: 범위 안의 그럴듯한 값으로 바뀐 손상, 원장·집계가 함께 일치하게 변한 손상, 악의적 작업자 쓰기, 미검사 영역·mutex 내부 손상. raw pointer 접근 전에 범위 검사 필요하나 모든 메모리 안전을 증명하지 않음.
복구 제안: mutex·원장·복구 기록이 신뢰 가능하고 집계만 불일치하면 재구성 가능 범위를 별도 정의. 신뢰 근거가 없으면 자동 복구 금지. 복구 가능한 영역을 어디까지로 볼지는 사용자 선택 필요.
진행/실패 제안: 발견 시 공유 분배 중단·부모 통지 → 부모 accept 중단·전체 작업자 종료. 그 전에 이미 전송한 HTTP 바이트를 철회할 수 없고 즉시 전원 동시 중단도 보장하지 않음. SIGTERM이 응답되지 않는 작업자의 강제 종료 기한은 별도 선택.
성공: 복구를 허용한 범위는 I1~I7 재검증, 그 외는 추정치로 운영하지 않고 승인된 종료. 새 정상 초기값으로 조용히 reset하지 않음.
비용: 변경한 항목은 O(1) 검사 제안, 전체 O(R+WB) 검사는 초기화·복구/명시 검증 시점 후보. 매 요청 전체 스캔/체크섬은 기본 채택하지 않음.
검증: 테스트 매핑의 잘못된 backend index·카운터·세대·원장·기록 magic/길이·통계만 변경. 실제 mutex 비트 무작위 손상 시 무기한 block까지 모두 탐지 가능하다고 주장하지 않음. 테스트 하네스 제한시간으로 hang 구분.

## 자료구조 대안과 정상 비용 — 선택 대기
A 추천 후보: 제한된 공유 요청 원장 + 작업자/세대/backend 기여분 + 집계 + 단일 mutex 보호의 제한된 복구 기록.
장점: 요청별 중복·잔류 증명, 사망 세대 회수·집계 재구성의 기준 존재. 비용: O(R) 메모리·원장 슬롯 관리·복구 스캔. 슬롯/원장 상한·원자 commit은 아직 미정.
B 대안: 공유 worker/backend 기여분 + 집계 + 작업자 로컬 token/완료 가드 + 제한된 복구 기록.
장점: 공유 요청 원장 O(R)을 줄임. 비용/한계: 로컬 기록은 작업자 사망 시 사라져 개별 완료·손상 진단·재구성 근거가 약함. 중간 갱신 복구·중복 반영 방지는 별도 설계 검증 필요, 기능 등가라고 단정하지 않음.
C 대안: 전체 상태 이중 사본/스냅샷 교체. 조회·복구 기준을 단순화할 수 있지만 사본 메모리와 복사·commit 프로토콜 비용. R개 요청 정보를 포함하면 단순 전체 복사는 매 갱신 O(R), 이번에는 비추천 후보.

정상 요청 제안 비용: backend 선택/예약 때 1회 mutex 구간, backend 완료/실패 반영 때 1회, 총 최소 2회. 헤더 조각·본문 청크마다 잠그지 않음. 충돌·보류 재시도 횟수는 별도 비용. 복구·취소·회수 경로는 추가 구간. 응답 시각은 I/O 밖에서 채집하고 잠금 안에서는 수치만 갱신.
선택 구간: backend 2개 상태 비교 + 한 예약/기여분·전체 카운터 + 순번/정책 상태 + 해당 복구 기록 commit. 완료 구간: token 대조 + 해제/기여분·전체 감소 + 합의한 통계 + 기록 commit. 시간·메모리 실측은 아직 없음.
공유 메모리 식: M = header/mutex + backend_state[B] + worker_state[W] + contribution[W][B] + reservation[R] + recovery_record[J] + alignment. B/W/R/J와 엔트리 크기 모두 설계 시 확정, R은 전체 공유 예약 슬롯 수이며 worker별 R이 아님.
예시만: uint64 기여분이면 8WB bytes, W=4/B=3은 96 bytes. 예약 한 칸이 32~64 bytes인 가정에서 R=10,000이면 320,000~640,000 bytes(약312.5~625KiB). 이 크기는 제안된 ABI/상한 확정이나 1만 처리 보장이 아니며, 통계/복구 기록·정렬·mutex/관리부·원장 탐색 보조 메모리 제외. 현재 mutex 40 bytes는 이 WSL ABI 관측값.
공유 매핑은 시스템 물리 메모리 1개를 여러 프로세스가 보는 것이며 프로세스 RSS 합계는 중복 집계될 수 있음. 연결별 header/body/relay buffer·커널 socket buffer·epoll·IPC·프로세스 스택은 별도 예산.

## 다음에 선택받을 복구 범위 묶음 (전부 미확정 제안)
1. worker crash/갱신 중 사망/중복 완료/복구자 재사망을 복구 대상으로, 손상 기록·불변 조건 실패·ENOTRECOVERABLE 등 복구 불가 시 전체 안전 종료. 그럴듯한 임의 손상 탐지 보장 제외.
2. 원장 A vs 집계 중심 B vs 이중 사본 C. 선택 후 구체 필드/크기/commit 원자성/메모리 순서·보류 재개·검증 범위를 다시 설명한다.
3. 상태 손상 검사는 제한된 구조 검증으로 하고 원장의 권위가 불명확하면 자동 재구성하지 않는 안 제안. 메모리 손상을 crash 복구와 혼동하지 않음.
4. 대체 작업자 생성/반복 장애 재시작 제한·부모 사망·강제 종료 기한은 다음 별도 선택. 이번 범위 합의가 재시작 승인 아님.
