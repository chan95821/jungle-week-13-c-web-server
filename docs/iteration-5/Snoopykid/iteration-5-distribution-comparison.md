# 조회 분배 알고리즘 비교 계획

2026-11-25 사용자 결정. 계획 기록이며 구현·성능 측정 실행 승인이 아니다.

## 확정과 미결정
- 부모가 accept하고 IPC로 작업자에게 클라이언트 FD를 전달한다. IPC 종류·작업자 선택·큐 상한·FD 인계 시점은 미결정이다.
- 조회 분배 상태는 서버 전체 작업자 기준으로 관리하는 방향을 채택했다. Round-Robin을 최종 알고리즘으로 확정하지 않는다.
- 각 후보가 필요로 하는 순번·진행 요청 수·응답 시간 상태도 전체 기준으로 검토한다. 구현 전에 공유 방식·동기화 비용·작업자 비정상 종료 시 회수 방안을 설명하고 선택받는다.

## 네 후보
| 후보 | 구체화할 동작 | 필요한 상태 후보 | 주요 검토 비용·한계 |
| --- | --- | --- | --- |
| Round-Robin | 순번에 따라 조회 A/B 선택 | 전체 순번 | 요청 비용·지연 차이 미반영 |
| Least Outstanding + 동률 RR | 진행 요청 수가 적은 곳, 동률 RR | 백엔드별 진행 수, 동률 순번 | 무거운 요청 1개와 가벼운 여러 요청을 동등 개수로 판단하는 한계 |
| 응답 시간 기반 + 동률 RR | 합의한 응답 시간 통계로 선택 | 백엔드별 시간 통계·표본 상태, 동률 순번 | 오래된 표본·빠른 오류·초기 표본 없음·선택 편향 |
| 진행 수와 시간 결합 점수 + 동률 RR | 합의한 점수로 선택 | 진행 수·시간 통계·표본 상태, 동률 순번 | 단위·가중치·중복 반영·복잡도·동기화 비용 |

어떤 후보도 현재 성능 우위나 최종 채택을 보장하지 않는다. 표의 상태는 설계 후보이며 아직 자료구조나 갱신 정책을 확정하지 않았다.

## 구현 전 합의 항목
- 진행 요청의 시작/종료: 선택·연결 시도·송신·최종 응답 수신 중 어느 시점부터 세는가. 연결 실패·본문 중단·클라이언트 종료·시간 초과·작업자 종료 시 정확히 한 번 해제.
- 응답 시간: 측정 시작/종료 구간, 단조 시계 사용, 첫 바이트/전체 응답 구분, 평균 방식·창/계수·초기값·표본 노후화.
- 결합 점수 공식·단위·가중치·범위·오버플로우/정밀도.
- 동률: 정확 일치/허용 오차·동률 순번 갱신 범위. 응답 시간 측정 방식 확정 전 숫자 제안의 채택으로 보지 않는다.
- 실패·시간 초과 표본 반영, 회복·미측정 백엔드 재탐색. 자동 우회/일시 제외를 묵시적으로 추가하지 않는다.
- 공유 수단 후보: 부모가 선택·예약·완료 통보를 조율 / 공유 메모리와 프로세스 간 동기화. 부모 IPC 병목·왕복, 공유 잠금 경쟁·일관성·소유자 사망 복구 비용을 비교한다.
- 작업자별 진행 요청 식별·세대·회수 기록의 필요성, 비정상 종료 후 중복 감소/잔류 카운트·부분 통계 갱신 방지. 정수 카운터만으로 자동 회복된다고 주장하지 않는다.

## 비교 시나리오 (미실행)
1. 정상: 동일 지연·본문 크기의 조회 A/B.
2. 느린 백엔드: 한쪽 고정 지연 및 시간에 따른 지연 변화.
3. 요청 비용 차이: 무거운 요청 1개와 가벼운 여러 요청, 혼합 본문·응답 크기.
4. 장애: 연결 거절·무응답·본문 중단·시간 초과, 작업자 비정상 종료 시 상태 회수.
5. 회복: 백엔드 정상화 후 표본 갱신·분배 회복·잔류 진행 수 확인.

후보마다 같은 작업자 수·연결 수·요청률·요청 구성/순서·백엔드 조건·빌드·기한·리소스 상한을 적용한다. 초기 상태와 워밍업·반복 순서 및 공유 상태 관리 방식도 기록해 알고리즘 외 차이를 구분한다. 장애 시 부하 조건과 기능 검증을 구분한다.

- 환경: WSL CPU/메모리·FD 한도, 서버·백엔드·부하 생성기 배치와 자원 경쟁.

- 지표 후보: 제출·조회 성공 처리량(req/s), 지연 p50/p95/p99(ms), 실패율·5xx·기한 초과율, A/B 도달 수·시간별 분포, 진행 수, 회복 시간.

공유 메모리 + 작업자 직접 선택을 채택했다. 부모 선택 조율 방식은 채택하지 않는다. API·잠금·복구·기여분·증감/통계·정책 입력 세부는 iteration-5-shared-state-design.md의 미결정 제안을 따른다. 경합·잠금 보유 중 종료·원장/카운터 회수·동일 비교 조건을 검증 후보로 추가했으며 실행은 보류한다.

## 사용자 확정 — worker에도 네 정책 선택 지원 (2026-11-25)
사용자 1번: worker 분배에도 RR / Least Outstanding+동률RR / 응답시간+동률RR / 진행수·시간 결합+동률RR 네 후보를 선택 실행할 수 있게 구현한다. backend와 후보 비교·점수·동률 계산을 공유하며 불필요한 범용 프레임워크는 만들지 않는다.
worker/backend 상태·순번·정책 설정·시간 측정·표본·실패 반영은 별도 관리한다. 양쪽에 같은 알고리즘을 강제하거나 최종 알고리즘을 확정한 것이 아니다. 기존 parent accept/FD 전달·worker backend 직접 선택·SOCK_STREAM 결정 유지.
worker의 outstanding 기준(미종료 연결/HTTP 처리중 요청), 시작·종료 시점, 부모 통보·세대별 회수, 시간 구간·평균·초기값·노후화·점수·동률·실패 반영은 미결정. backend 통계의 의미를 worker에 자동 적용하지 않는다.
worker/backend 정책을 동시에 바꾼 결과를 한 알고리즘의 효과로 해석하지 않도록 비교 계획에서 다른 층의 정책을 고정하는 조건을 먼저 제시한다. 조합 비교·부하·성능 실행은 별도 허락 필요. 이번에는 코드·검증·성능을 실행하지 않았다.

## worker outstanding 기준 확정 — 사용자 1번 (2026-11-25)
worker 정책의 진행 수는 배정 후 아직 종료되지 않은 클라이언트 연결 수로 한다. 헤더/본문 수신 중·백엔드 대기·응답 전송/마무리 중 연결을 포함하고, 실제 HTTP 처리 중 요청 수만 세는 안은 미채택이다. backend outstanding 시작/종료 시점까지 확정한 것은 아니다.
parent가 배정 상태를 보유하고 worker의 연결 종료 통보로 반영하는 방향. 정확한 배정 증가 시점/미전달 취소·worker 사망·중복/늦은 종료 통보 처리와 queue 상한·ACK는 여전히 미정이다. 연결 ID+worker generation을 기준으로 중복 감소/새 세대 오염 방지를 설계한다. worker/backend 측정값은 별도이며 정책도 최종 미확정.

### 다음 FD 인계 선택안 (미확정)
1 추천: STREAM의 FD 포함 프레임 전체가 전송되면 parent 원본 FD close, 수신 ACK는 요구하지 않음. 첫 양수 sendmsg에 SCM_RIGHTS는 이미 전달될 수 있으므로 fd_sent flag를 두고 나머지 바이트에는 ancillary를 재전송하지 않음. parent는 whole-frame 완료까지 원본을 보유하되 client I/O는 하지 않음. worker는 프레임 전체 검증 전 client 처리 시작 금지 제안.
2 대안: 프레임 전체 전송 후에도 worker 수신/등록 ACK까지 parent 원본 보유. 등록 여부를 명시 확인할 수 있지만 추가 IPC·ACK 대기 원장·FD/기한 비용이 필요. ACK는 HTTP 완료나 worker 생존 보장이 아니며, 성공 전송 후 ACK 소실을 이유로 다른 worker에 재배분하면 중복 처리 위험이 있다.
두 안 모두 첫 FD 전송 양수 성공 이후 같은 연결을 자동 재배분하지 않는 안을 함께 제안한다. 전체 프레임 미완료 상태의 채널 단절/worker 종료 시 각 보유/수신/queued 참조를 정리해야 한다. 위 내용은 선택안이며 아직 구현하지 않는다.
