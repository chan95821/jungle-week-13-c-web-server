# Iteration 5 — B: 고정 스레드 + 작업자별 epoll

기준: `iteration5/jaeseong`, `678df2c` (부모 `577a554`). 팀 채택 선언이 아닌 개인 후보 구현이다.

## 사용자 결정과 구현 경계

2026-11-25 사용자가 B를 선택하고 “너가 선택해서 … 완성”을 요청했다. 아래 세부 설계는 이 위임에 따라 선택한다.

- 프로세스 하나, 수락 담당 하나, 시작 시 생성하는 고정 네트워크 작업자(기본 4개). 각 작업자는 epoll 인스턴스 하나와 여러 연결을 소유한다.
- Linux/WSL2의 nonblocking socket, level-triggered epoll, eventfd, signalfd를 사용한다. Linux 전용 부분은 새 이벤트 모듈에 둔다.
- 수락된 FD는 상한 있는 작업자 큐로 전달한다. 연결은 종료까지 한 작업자만 수정한다. 조회 A/B 선택만 짧은 mutex로 보호하여 전체 공통 RR 순번을 유지한다.
- 파일 경로 확인·파일 읽기·CGI 준비/읽기/정리는 고정 보조 I/O 풀에서 수행한다. 네트워크 연결 전체를 blocking 작업에 맡기는 C 모델과 구분한다. 기본 보조 작업자 2개, 대기 큐 256개. 정리 작업이 밀려도 연결 소유권을 놓치지 않는다.
- 요청 헤더 8KiB, 본문 64KiB. 백엔드 응답은 16KiB 조각을 전송하고 조각 전송 완료 전에는 같은 버퍼를 덮어쓰지 않는다. 느린 클라이언트에는 백엔드 읽기를 멈춰 TCP 역압을 적용한다.
- 연결마다 시간 제한을 저장하고 작업자의 최소 힙에서 가장 가까운 만료 시점을 찾는다. EAGAIN은 오류가 아닌 대기 상태다. 이벤트별 처리량을 제한해 한 연결의 독점을 줄인다.
- 작업자 큐 256개, 작업자당 수락 예약을 포함하여 최대 4096연결. 전체 작업자가 가득 차면 새 연결을 닫는다. FD 한도가 먼저 적용될 수 있다. 10,000연결 지원을 측정으로 보장하지 않는다.
- 기존 요청/라우팅/헤더·본문 계약과 백엔드 타임아웃을 유지한다. 본문 전체 제한 15초는 클라이언트 송신 대기도 포함한다. 백엔드 idle 5초는 백엔드 읽기를 실제로 기다리는 동안 적용하며 클라이언트 역압 후 다시 시작한다.
- 정상 응답 후 SHUT_WR와 최대 1초/64KiB 입력 배출도 이벤트로 수행한다. 중간 응답 실패 시 추가 HTTP 오류나 완료 zero chunk를 쓰지 않는다.
- SIGINT/TERM은 관리 스레드의 signalfd에서 받고 작업자에 종료를 알린다. 진행 응답 완료는 보장하지 않는다. 보조 작업 중인 연결은 결과/정리 완료까지 메모리를 유지한다.
- `init`에서 삭제되었으나 Makefile/회귀가 참조하는 CGI 데모와 카페 리소스만 부모 기준에서 복구한다. 기존 HTTP 정책을 과거 개인 구현으로 되돌리지 않는다.

## 제외

keep-alive, HTTPS/CONNECT, 백엔드 재시도·자동 우회, 상태 동기화, 신규 분배 알고리즘, 성능 자동 측정·최적화, 팀 기준 채택/병합.

## 확인 상태

공식 검증 실행 보류는 유지한다. 컴파일은 수행할 수 있다. 기능 검증과 성능 측정의 조건/허락은 별도로 확정한다. 기존 Ubuntu의 VHDX가 없어 실행되지 않아, 사용할 수 있는 Debian WSL에서 빌드 도구를 준비한다. Ubuntu 환경 검증을 대신 통과했다고 주장하지 않는다.
