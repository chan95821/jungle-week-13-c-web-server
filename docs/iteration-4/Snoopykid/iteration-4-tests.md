# Iteration 4 검증 후보

작성일: 2026-11-24. 실행 허락이나 통과 결과가 아닌, 구현 전 누적하는 검토 범위다.

## 설정·경로·분배 흐름

| 항목 | 목적과 통과 기준 |
| --- | --- |
| 설정 읽기 | 확정한 설정 파일로 시작하고 잘못되거나 누락된 필수 설정은 리스닝 전에 거절한다. 세부 파일 문법·주소 범위는 추가 설계에 따른다. |
| 제출 목적지 | POST /api/submissions가 제출 백엔드에만 도달한다. |
| 조회 목적지 | GET /api/submission-status와 GET /api/hello가 조회 A/B로 분배된다. |
| Round-Robin | 초기 A부터 A/B 선택을 반복하며 두 조회 경로가 하나의 조회 풀 순번을 사용하는 안은 구현 전에 명시한다. 제출 요청은 조회 순번을 소비하지 않는다. |
| 실패 후 선택 | 선택 시 순번을 넘기고 동일 요청을 다른 서버에 자동 재시도하지 않는다. 다음 요청은 다음 순번을 사용한다. |
| 경로·쿼리 보존 | 백엔드에 원래 요청 대상 바이트를 전달한다. |
| 기존 라우팅 | 현재 정적·동적 기능과 메서드·오류 정책을 보존한다. |

## 중계·오류 흐름 — 세부 정책 확정 후 구체화

- #4의 필수 중계와 #17의 제출·조회 계약을 유지한다.
- POST 본문과 바이너리 응답을 바이트 단위로 비교하고 상태 코드·전달 대상 헤더를 확인한다.
- 백엔드 연결 거절, 무응답, 응답 도중 중단·타임아웃, 클라이언트 갑작스러운 종료를 재현한다.
- 잘못된 요청, 큰 본문, 긴 URI의 기존 정책을 유지한다.
- 최종 응답 송신 시작 후 새 오류 응답을 덧붙이지 않는다.
- 반복 오류 뒤 서버 생존, 메모리·FD 정리를 확인한다.
- 테스트 백엔드는 기존 C 서버 코드를 재사용하고 프록시 코드와 분리한다. Python은 프로세스 제어·요청·결과 검증 스크립트에만 사용한다.
- 오류 주입 방식·응답 계약·타임아웃 조건은 설계 확정에 맞춰 목적·통과 기준을 추가한다.

## 제외 및 후속 검토

- 공식 검증은 구현 후 사용자와 범위를 확정한 뒤 실행한다. 컴파일·링크 확인과 구분한다.
- 성능·부하 실험은 조건 제안과 별도 허락 전에는 실행하지 않는다.
- 무거운 요청 1개 대 가벼운 요청 여러 개의 반례, 여러 작업자 상태 공유, 역압력과 동시 연결 목표는 Iteration 5에서 검토한다.

## 설정·선택 모듈의 구현 전 기본 케이스

- 정상 설정·주석·빈 줄·줄바꿈 없는 마지막 줄을 읽고 제출/A/B의 주소·포트를 보존한다.
- 누락·중복·알 수 없는 역할, 호스트명·IPv6·잘못된 IPv4, 포트 0/65536/문자열, 추가 토큰·입력 NUL을 거절한다. 실패 시 이전 출력 설정을 보존한다.
- GET /api/submission-status와 GET /api/hello는 같은 조회 풀을 선택한다. POST /api/submissions는 제출 목적지다.
- 확정 경로의 잘못된 GET/POST는 405와 Allow, 미구현 메서드는 기존 정책 501이다. /hello·/assets 등 다른 경로는 기존 라우터로 넘긴다.
- 조회 A→B→A 선택, 제출 사이에 섞어도 조회 순번 유지, 잘못된 메서드·로컬 경로는 선택 상태를 변경하지 않는다.
- 목적지 판별·선택은 요청 target과 body를 변경하지 않는다. 두 개의 선택 상태가 서로 독립적이며 전역 가변 상태가 없다.
- 위 테스트는 컴파일만 확인한다. 공식 테스트 실행 허락은 별도다.

## 중계 함수 구현 전 검증 후보 보강

- 응답 HTTP/1.1 상태·중복 end-to-end 헤더·바이너리 본문 보존, Host 재작성, Via 추가, hop-by-hop 및 Connection 지명 헤더 제거.
- Content-Length 0/분할/조기 EOF/중복·충돌·오버플로우, chunked 분할·청크 확장·종료·트레일러·잘못된 청크, 길이 없는 연결 종료 응답.
- HTTP/1.0과 101은 502, 1xx 다음 최종 응답, 204/304의 본문 없음 규칙.
- 연결 거절 502, 무응답 3초 대비 헤더 기한 1초 504, 응답 본문 중단·무진행·전체 기한에서 추가 HTTP 오류 없음.
- 임시 C 백엔드 프로세스만 제어한다. Python HTTP 서버는 만들지 않는다. 반복 장애 뒤 FD 수·생존, 신호 취소 경로를 확인한다.
- 현재는 컴파일·구문 확인만 한다. 공식 검증은 구현 후 범위 확인을 거쳐 실행한다.

테스트용 파일·권한 변경은 임시 fixture로 한정한다. 실제 정적 루트·운영 권한·사용자 설정 예시를 변경하지 않는다. /proc 또는 권한 조건에 따른 기존 테스트 skip은 결과에 구분한다.

제외: 부하·성능 측정, 동시 연결 1만 개 실험, 광범위한 퍼징/경합, 실제 운영 ACL 보증, 모든 메모리 할당·시스템 호출 실패 조합과 연결 타임아웃 네트워크 장애 주입. 연결 거절과 응답 시간 초과를 연결 완료 기한 검증으로 확대하지 않는다.

make test / make verify를 사용자 승인 후 실행하고 통과·실패·skip·미검증으로 보고한다. 서버 E2E 바이너리는 일반 -O2이며 단위 sanitizer 검사와 구분한다.
