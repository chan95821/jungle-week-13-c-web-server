# P0-2 보완 및 검증 결과

날짜: 2026-11-25. 기준 f32e17d, 로컬 Iteration4/Proxy-YYJ의 미커밋 보완이다. main 머지·커밋·푸시는 수행하지 않았다.

## 기존 결정과 신규 변경

| 항목 | 처리 | 평가 분류 |
| --- | --- | --- |
| Host | 기존 백엔드 IPv4:port 재작성 유지 | C2의 원본 보존 기대와 팀 계약 차이. 이 결과를 현재 정책의 구현 결함으로 재분류하지 않는다. |
| Connection 보호 필드 | 새 400 오류 정책 구현 | P0-2에 해당하는 실제 코드 보완 |
| CLI | 설정 파일 필수 유지 | C14의 포트 단독 실행 기대와 계약 차이. 내장 기본 백엔드 추가 및 회귀 스크립트 원복 없음. |
| HTTP/1.0 | HTTP/1.1 전용 유지 | C7과 지원 범위 차이. 변경 승인 없음. |
| 타임아웃·소유권·분배 | 기존 확정 기록 유지 | P1/P2 제안은 자동 승인·자동 구현하지 않는다. |

외부 평가의 원래 실패 결과와 수치를 삭제하거나 바꾼 것이 아니다. 이 문서는 그 결과와 현재 확정 계약의 차이를 구분한다. 외부 교차 테스트 전체 및 Go 성능 벤치마크는 재실행하지 않았다.

## 구현 흐름

handle_client → http_parse_request → proxy_match_request → validate_proxy_connection_options.

기존 프록시 경로·메서드 판별 뒤, 정상 경로를 확정하기 전에 모든 Connection 줄을 검사한다. 옵션은 쉼표로 나누고 SP/HTAB를 제거한 전체 토큰을 대소문자 없이 비교한다. Host·Content-Length·Transfer-Encoding이면 400을 반환한다. 입력 복사·수정·할당·I/O·전역 가변 상태는 추가하지 않는다.

400은 기존 respond 경로로 이어지므로 본문 할당·추가 수신, 100 Continue, 백엔드 선택·연결을 실행하지 않는다. 기존 구문/길이 파싱·405/501 우선순위, 로컬 경로, 일반 지명 헤더 제거는 유지한다. 헤더 recv에 동반 도착한 데이터와 종료 시 제한적 수신 폐기는 기존 동작이다.

## 실행 결과

| 구분 | 결과 |
| --- | --- |
| make clean | 성공. 명시한 산출물만 정리 |
| make all | 컴파일·링크 성공 |
| make test | 7개 단위 테스트 통과, ASan/UBSan 오류 보고 없음 |
| make verify | 5개 E2E 스크립트 통과 |

| git diff --check | 공백 오류 없음. LF/CRLF 변환 경고만 있음 |
| 최종 기능·회귀 테스트 실패 | 없음 |
| skip | 없음 |

개발 중 E2E 호출을 삽입하면서 재시작 분기에 중복 삽입된 들여쓰기 오류를 구문 확인에서 발견했다. 중복 호출을 제거한 뒤 구문 확인과 전체 E2E를 통과했다. 운영 정책 변경이나 검증 조건 완화는 하지 않았다.

새 단위 검사는 세 프록시 경로 × 보호 필드/대소문자/OWS/복수 Connection/유사 문자열/일반 옵션을 확인한다. 로컬 경로와 기존 405/501도 확인한다.

새 E2E는 Content-Length: 10과 Expect: 100-continue를 헤더만 보낸다. 본문 전송 전에 첫 응답이 최종 400이며 100이 없음을 확인했다. 별도의 수동 TCP 리스닝 소켓으로 백엔드 접속이 0건임을 확인했다. 이 소켓들은 HTTP 응답을 제공하지 않는 검증용 접속 감지기이며, 실제 응답 백엔드는 기존 C 코드다. 정상 조회 A부터 시작, 일반 X-Hop 201/제거, 로컬 /hello 200도 통과했다.

기존 회귀는 바이너리 본문·상태/헤더·Host 재작성·Via·프레이밍·502/504·응답 도중 실패·FD 누적 방지·시그널 종료를 포함했다. 종료 반응을 정확히 0초라고 보장하거나 전 프로토콜 준수로 확대하지 않는다.
