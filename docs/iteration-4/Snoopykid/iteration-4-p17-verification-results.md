# P1-7 엣지 검증 통합 결과

날짜: 2026-11-25. 기준 브랜치 Iteration4/Proxy-YYJ. 이전 P0-2·HTTP/1.0·P1-6 미커밋 변경을 보존했다.

## 변경 범위와 실행 흐름

참고 커밋 eda192c의 verify_edge_cases.py에서 34개 검증 아이디어를 가져오고 현재 계약에 맞췄다. scripts/verify_edge_cases.py가 기존 verify_iter4의 Fixture와 요청/응답 helper를 사용해 C 테스트 백엔드 및 프록시를 시작하고, 요청 전송 → 응답/생존/FD 확인 → 프로세스와 임시 설정 정리 순으로 실행한다. Python HTTP 백엔드는 추가하지 않았다.

테스트용 C 백엔드에 지연·부분·slow-drip 헤더, 진행하는 느린 본문, 요청 수신 알림 모드를 추가했다. Makefile에 make verify-edge를 추가하고 make verify의 마지막 단계에도 포함했다. src/의 17개 파일은 작업 전 SHA256과 모두 같으며 이번 보완에서 제품 동작·자원 소유권은 바꾸지 않았다.

## 검증 범위와 계약 차이

E01~E34는 잘못된 요청/버전/헤더, EOF·호출별 타임아웃, 긴 URI·8KiB 헤더, 64KiB 본문 경계와 초과 거절, 길이 없는 echo의 추가 데이터, 바이너리 중계, 느린 백엔드, 오류 후 생존·FD 회수 및 응답 도중 중단을 확인한다.

추가 6개는 C2/C3/C7/C12/C13/C14 대응 사례다. C2는 합의된 Host 재작성, C14는 설정 파일 필수를 검증한다. 원본 교차 테스트의 Host 보존·선택적 CLI 기대값을 채택하거나 그 차이를 구현 결함으로 판정하지 않는다. C3은 보호 필드 지명 시 100 Continue·본문 수신·백엔드 연결 전 400을 확인한다. C7은 백엔드 HTTP/1.0 정규화, C12는 바이트가 계속 도착해도 전체 헤더 기한이 늘어나지 않음, C13은 C 백엔드 수신 알림 확인 후 SIGTERM 종료를 확인한다.

지연 헤더는 현재 전체 1초 기한으로 504, 본문 idle은 기존 5초다. 클라이언트 HTTP/1.0은 여전히 505다. C13의 0.75초 대기 상한은 기능 테스트의 종료 판정 조건이며 측정된 종료 지연이나 운영 SLA가 아니다.

E25는 413을 먼저 확인한 뒤 제한된 추가 전송과 서버 복구를 확인한다. 동시 대량 전송 중 TCP reset에도 응답 전달을 보장하거나, 전체 추가 데이터를 애플리케이션이 읽었다고 주장하지 않는다. 기존 최대 1초/64KiB 폐기 정책을 유지한다.

## 미검증·후속 범위

외부 교차 스위트 전체, 광범위한 퍼징·경합, 실제 운영 권한은 검증하지 않았다. 부하·처리량·지연 분포·CPU·메모리 성능 측정도 하지 않았다. 테스트의 시간 제한은 기능상 완료/종료 판정에만 사용했다. 임시 fixture만 사용했고 운영 정적 루트·권한을 바꾸지 않았다.

P1-5 타임아웃 변경, P2 파일 분리·버퍼 수명/할당 개선, 라우팅 일원화·IPv6·가변 백엔드·동시성은 포함하지 않았다. main 머지·커밋·푸시는 수행하지 않았다.
