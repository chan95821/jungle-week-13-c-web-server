## 확인한 동작
- 기존 포트/요청 수신/부분 송신/파서와 Hello·echo, 조각 수신·길이 경계·추가 데이터·100 Continue 회귀.
- 정적 파일의 바이트/MIME/Content-Length, 단일 디코딩·점 경로·반복 슬래시·디렉터리·링크·비정규 파일·OS 이름 길이 정책.
- /greet의 입력에 따른 다른 응답, 누락/빈 값/중복, 디코딩한 키, 구분 후 디코딩, 모든 키·값 UTF-8/제어문자 검사.
- 실제 임시 파일 truncate 후 조기 EOF, 증가분 제외, 같은 파일시스템 rename 뒤 이전/새 FD 차이.
- 결정적 short read/send·EINTR·읽기/송신 오류·취소, 최종 헤더 후 두 번째 오류 응답 없음.
- 실제 서버 클라이언트 reset 뒤 생존, 정상/오류 반복 뒤 /proc FD 기준 복귀.
- 임시 fixture의 읽기 권한 거절과 잘못된/읽을 수 없는 루트의 시작 실패.

## 환경·정리
Ubuntu WSL2, 실행 계정 유효 UID 1000.
단위 테스트는 -fsanitize=address,undefined로 빌드된 실행 파일이며 이번 실행에서 sanitizer 오류 보고는 없었다. 이는 실행된 경로의 결과이며 서버 전체 누수/메모리 오류 부재를 증명하지 않는다. E2E 서버는 기존 -O2 빌드다.
테스트 후 pgrep -a -x server에서 잔여 server 프로세스가 없음을 확인했다.
내용/권한 변경은 /tmp 기반 테스트 fixture에 제한했다. 프로젝트 public과 운영 권한을 바꾸지 않았다. 실제 운영 권한 계약 충족을 확인했다고 주장하지 않는다.
원인 수정·정책 변경·성능 측정·커밋·푸시는 하지 않았다.
