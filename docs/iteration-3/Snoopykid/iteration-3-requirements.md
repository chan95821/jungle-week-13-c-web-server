## 사용자 확정
- 실행: ./build/server <port> <document-root>. 정적 루트 필수.
- /static/ 접두사를 제거한 경로를 정적 루트 아래에 매핑한다.
- 기존 GET /, GET /hello, POST /echo 동작을 유지한다.
- /static/ 자체와 실제 디렉터리 요청은 403으로 거절한다. index.html 자동 제공·디렉터리 목록은 구현하지 않는다.
- 요청 경로의 파일·중간 디렉터리 심볼릭 링크는 모두 거절한다. 루트 FD 기준으로 각 요소를 openat로 열고 링크를 따라가지 않는 방식을 선택했다.
- 원래 path에서 /static/을 판별하고, 쿼리와 분리된 파일 경로 부분만 한 번 디코딩한다. 인코딩된 슬래시·역슬래시·NUL·제어문자는 400으로 거절하고 반복 디코딩하지 않는다. 기존 동적 경로 해석은 유지한다.
- 디코딩 후 . 또는 .. 세그먼트가 있으면 정규화하지 않고 403으로 거절한다.
- CLI document-root는 시작 시 OS 경로 해석으로 디렉터리로 열어 FD를 유지한다. 설정한 루트의 링크는 허용한다. 열기 실패 또는 디렉터리가 아니면 오류 출력 후 시작을 중단한다.
- 파일 전송·MIME·greet의 최종 선택은 아래 기록을 따른다. 현재 구현 완료·컴파일 확인 후 공식 검증 범위 검토 단계다.
- 루트 밖 접근 방지와 큰 파일의 버퍼 크기 독립 전송은 Issue #3 필수 범위다.
- 이전 개인 공식 검증·성능 측정 미실행 기록은 팀 채택/병합 상태와 구분한다.

## 범위 밖
- Reverse Proxy는 Iteration 4. CGI·별도 백엔드 전달은 이번 필수 범위가 아니다.
- 사용자 선택 전 정책 자동 변경, 공식 검증 실행, 성능 측정·비교 실험을 하지 않는다.
## 파일 전송·응답 형식 선택
- 열린 파일을 fstat로 확인하고 임시 16KiB 버퍼를 재사용하여 read와 기존 부분 송신 처리를 반복한다. 파일 전체 크기의 메모리는 할당하지 않는다.
- 16KiB는 최적값이 아닌 임시값이다. 전송 중 파일 변경 정책은 별도 사용자 선택 전이다.
- GET /greet?name=Alice는 text/plain; charset=utf-8 및 Hello, Alice!와 줄바꿈으로 응답한다. 입력 세부 규칙은 아래 쿼리 검사 확정 기록을 따른다.
- MIME은 html/htm=text/html, css=text/css, js=text/javascript, png=image/png, jpg/jpeg=image/jpeg. 확장자는 대소문자 없이 비교하고 나머지는 application/octet-stream. 파일 내용 추정은 하지 않는다.
## 최종 경로·전송 소유권 선택과 구현 연결
- 정적 GET만 지원. POST는 파일 존재 검사 전 405 + Allow: GET. 기존 미구현 메서드 501 유지.
- /static은 404. 반복 슬래시는 400. 끝이 /인 정적 요청과 디렉터리는 403.
- 없음/중간 요소가 파일이면 404, 권한/심볼릭 링크/비정규 파일은 403, OS 이름 길이 초과 414, 기타 내부 오류 500.
- 응답은 메모리/파일 종류, 열린 파일 FD, 길이를 가진다. handle_client가 파일 FD와 생성 본문을 소유/정리하고 송신 함수는 빌려 쓴다. 디코딩 경로 배열은 기존 헤더 상한+NUL로 유도한다.
- 파일은 최초 fstat 길이까지만 전송. 증가분 제외, 조기 EOF/읽기/송신 오류는 기록 후 연결 정리. 이미 최종 헤더를 보낸 후 오류 응답을 추가하지 않는다. 동일 크기 덮어쓰기/내용 스냅샷은 보장하지 않는다.
- 정적 트리를 수정할 수 있는 계정과 동시 파일/디렉터리 변경은 신뢰 경계 및 운영 제한이다. 권한과 새 파일+rename 불변 게시 절차는 아래 운영 계약으로 문서화한다. 실제 환경 충족을 확인하지 않았으며 자동 설정하지 않는다.
- /greet는 구분자를 먼저 나누고 키/값을 한 번 디코딩. 디코딩한 키로 name과 중복을 판별한다. 누락 World, 빈/중복 name 400, 알 수 없는 키 의미 무시, +는 쿼리에서만 공백이다. UTF-8/제어문자의 검사 범위는 사용자 추가 선택 전이다.
- main → static_open_root → open_listenfd → accept → handle_client(root FD 차용) → parse/route → 본문 수신 → static_open_file 또는 메모리 응답 준비 → send_response → 공통 자원 정리 → main의 연결 close. main이 루트 FD를 닫는다.
## 쿼리 검사·게시 운영 계약 확정
- /greet의 알려진/알 수 없는 모든 키·값을 디코딩 후 검사한다. 현재 구현 기준은 올바른 UTF-8, U+0000~001F/U+007F~009F 금지이며 과잉 인코딩·대리 코드 포인트·U+10FFFF 초과를 거절한다.
- 이 인코딩/제어문자 범위는 이번 구현 기준이며, 검증 체크포인트에서 확대 여부를 다시 선택한다. 자동 확대·정규화·정적 경로 정책 변경은 하지 않는다.
- 서버 계정은 정적 트리 읽기/탐색만, 신뢰하는 게시자만 수정, 기존 inode 덮어쓰기 금지, 같은 파일시스템에 새 파일을 완성·닫고 rename으로 교체하는 운영 계약을 문서화한다.
- 악의적인 디렉터리 이동/교체·권한 있는 게시자의 콘텐츠 변경은 지원 보장 밖이다. 실제 권한 조건 충족은 아직 확인하지 않았다. 권한 자동 변경·게시 스크립트는 제외한다.
## 구현 결과·현재 제한
static.c/h, greet.c/h를 추가하고 main의 루트 FD 수명과 server의 파일 송신/정리를 연결했다. 파일 길이는 uintmax_t로 관리하며 파일 전체 메모리 할당은 하지 않는다.
서버와 일곱 단위 테스트의 컴파일·링크, 세 Python E2E의 구문 확인에 성공했다. 공식 테스트·sanitizer 런타임·서버·curl·성능 측정은 실행하지 않았다. 팀 통합/Iteration 완료 판정은 별도다.
인코딩/제어문자 범위 확대 여부, 실제 권한 검토, 공식 실행 범위는 검증 체크포인트에서 다시 확인한다. 함수 흐름은 iteration-3-walkthrough.md, 게시 운영 제한은 iteration-3-publishing.md에 기록했다.
