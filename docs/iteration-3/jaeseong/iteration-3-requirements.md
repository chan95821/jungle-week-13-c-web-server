# Iteration 3 정적 파일 서빙: 개인 구현 범위

현재 브랜치: iteration3/jaeseong. 기준: 과제 원문, 현재 소스, AGENTS.md 및 사용자의 2026-11-23 선택.
GitHub Issue #3는 CLI 인증 부재로 확인하지 못했다. 팀 이슈 대조·통합 완료로 표시하지 않는다.

## 선택한 동작

- 기존 GET /, GET /hello의 Hello와 POST /echo 보존.
- GET /static/ → 문서 루트/index.html, GET /static/a/b → 문서 루트/a/b.
- 실행 인자 `[document-root]`, 생략 시 public. 설정한 루트는 시작 시 한 번 열어 main이 소유.
- /static 접두사는 원래 경로에서 판정하고, 이후 상대 경로만 한 번 디코딩. 쿼리는 파일명에 포함하지 않음. +는 경로에서 그대로 유지.
- 400: 잘못된 인코딩, 디코딩된 NUL/제어 문자/역슬래시, 빈 경로 요소.
- 403: . 또는 .. 요소, 심볼릭 링크(중간 포함), 권한 거부, 디렉터리/특수 파일.
- 404: 파일 또는 중간 디렉터리 없음/일반 파일을 중간 디렉터리로 사용.
- 500: FD 고갈, 메타데이터 확인 실패 등 서버 내부 오류.
- 파일명·확장자는 디코딩된 경로 기준. HTML/CSS/JS/PNG/JPEG/GIF/SVG 및 기본 application/octet-stream.
- 파일은 크기 제한으로 전체 할당하지 않고 일정 크기 버퍼로 전송. 처음 확인한 길이까지만 전송.
- 파일 변경으로 전송 도중 EOF/오류가 나면 연결 종료. 헤더 전송 후 새 500 응답을 덧붙이지 않음.

## 기존 계약 유지

HTTP/1.1 origin-form·요청 길이 상한·수신 기한·100 Continue·호출별 송신 제한·제한적 연결 폐기·HEAD 미지원 정책 유지.
라우터는 경로를 판정하고 메모리 응답을 선택하며, 파일 I/O는 새 모듈과 server.c가 수행한다.
요청 데이터는 원본 버퍼의 slice를 유지하고 파일 경로는 별도 버퍼에서 처리한다.

## 제외

정적 파일 쓰기/업로드, 디렉터리 목록, 하위 디렉터리 index 자동 탐색, Range/캐시/압축,
HEAD 기능 확장, sendfile/mmap 최적화, 프록시·동시성·부하 및 성능 측정.

## 탑다운 흐름

main → 루트 열기 → 연결 수락 → handle_client → 헤더/요청 파싱 → 라우팅
→ 정적 파일이면 경로 검사/openat/fstat/MIME 준비 → 기존 요청 본문 수신
→ 응답 헤더 → 파일 read/send 반복 → 기존 연결 마무리 → 파일 close/본문 free
→ main에서 연결 close → 서버 종료 시 루트 close.
