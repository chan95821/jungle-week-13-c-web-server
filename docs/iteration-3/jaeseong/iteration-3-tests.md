# Iteration 3 테스트 기준 (구현 전 정의)

## 단위 검증 후보

- /static/ GET 판정, POST 405+Allow, 기존 경로와 미지원 메서드 정책 유지.
- 실제 파일 준비: /static/ 기본 index, 하위 파일, 쿼리 제외 계약, 퍼센트 파일명, + 보존.
- 원본 slice 불변, NUL/제어 문자/역슬래시 및 잘못된 퍼센트 400.
- 원문/디코딩된 . 및 .., 마지막/중간 심볼릭 링크, 디렉터리/특수 파일 403.
- 없는 파일·없는 디렉터리·일반 파일을 중간 경로로 사용 시 404.
- 파일 크기와 MIME: HTML/CSS/JS/PNG/JPEG/GIF/SVG/미등록 확장자/대문자 확장자.
- 서버 내부 오류 500, 실패 후 file.fd=-1, 호출자 루트 FD 보존 및 정리.

## 실제 서버 검증 후보

- 샘플 HTML/CSS/PNG 및 curl 응답의 상태·MIME·Content-Length·본문 바이트.
- 0바이트, 전송 버퍼 경계 전후, 64KiB보다 큰 바이너리 파일 무결성.
- 400/403/404/405/500 분류와 오류 이후 정상 요청 처리.
- 읽기 권한 없는 파일/디렉터리의 실제 403: Linux 파일시스템에서 비루트로 실행.
- 루트 밖 접근·중간/마지막 symlink 차단. curl --path-as-is 또는 원시 소켓 사용.
- 정적 GET의 선언 본문 및 Expect 흐름, 기존 Hello/echo·1/2단계 회귀.
- 서버 시작 시 잘못된 루트, 원래 작업 디렉터리와 다른 루트 인자.
- 클라이언트 중단 후 복구, 파일/소켓 자원 반환의 기본 확인.
- ASan/UBSan 빌드에서 기본 단위/E2E 확인. 대규모 오류 주입·경합·부하는 제외.

## 실행 상태

아직 구현 전 기준이다. 구현 종료 후 환경·항목·통과 기준·제외 범위를 사용자에게 제시하고 확정 후 실행한다.

## 사용자 최종 검증 범위 (2026-11-23)

사용자 지시: `정적 파일 기본 기능만 검증. 더 나가지마`.
위 넓은 후보 목록은 실행 허가가 아니다. 이번에는 아래만 실행한다.

- HTML/CSS/SVG 및 임시 PNG의 200, MIME, Content-Length, 원본 바이트 일치.
- 비루트 서버의 읽기 권한 없는 파일에 대한 403.
- 없는 파일에 대한 404.
- 실행 명령: `make verify-static` (일반 빌드). 테스트 메서드는 3개다.

기존 회귀/단위 실행, sanitizer 실행, 경로 조합·경계·오류 주입·부하/성능은 실행하지 않는다.
서버 컴파일 및 Python 구문 확인은 기능 검증 실행과 구분한다.
